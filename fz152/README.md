# Сканер сайтов по 152-ФЗ

Инструмент для поиска клиентов на услугу «приведение сайта в соответствие с законом о персональных данных».
Он обходит список сайтов, находит признаки нарушений и для каждого сайта готовит:

- **отчёт для клиента** (HTML, легко сохранить в PDF): чек-лист, найденные проблемы, почему это важно и как исправить, с подсказками для Tilda и GetCourse;
- **черновик письма** с 2–3 главными замечаниями и адресом для связи;
- **сводную таблицу** (`index.html` и `leads.csv` для Excel), отсортированную по серьёзности — сверху самые «горячие» сайты.

Пример отчёта: [`examples/report-concept-lingva.html`](examples/report-concept-lingva.html), пример письма: [`examples/letter-concept-lingva.txt`](examples/letter-concept-lingva.txt).

## Что проверяется

| Проверка | Уровень | На что опирается |
|---|---|---|
| Формы собирают имя, телефон или e-mail без согласия | серьёзно | ст. 9 152-ФЗ |
| Нет политики обработки ПДн или ссылка на неё битая | серьёзно | ч. 2 ст. 18.1 152-ФЗ |
| Сайт без HTTPS, хотя на нём есть формы | серьёзно | ст. 19 152-ФЗ |
| Заявки уходят в Google Forms, Typeform и т. п. | серьёзно | ч. 5 ст. 18 152-ФЗ (локализация) |
| Согласие только фразой «Нажимая кнопку…», галочка отмечена заранее, согласие склеено с офертой | средне | ст. 9 152-ФЗ, ред. с 01.09.2025 |
| Нет отдельного документа согласия | средне | ст. 9 152-ФЗ, ред. с 01.09.2025 |
| Галочка согласия на рекламу отмечена заранее | средне | ч. 1 ст. 18 закона «О рекламе» |
| Google Analytics, reCAPTCHA, Meta Pixel и др. (трансграничная передача) | средне / незначительно | ст. 12 152-ФЗ |
| Вебвизор включён, а в политике аналитика не описана | средне / незначительно | ст. 18.1 152-ФЗ |
| Cookie аналитики без уведомления; не указаны ИНН и ОГРН | незначительно | рекомендация |
| Уведомление в Роскомнадзор | проверить вручную | ч. 10 ст. 13.11 КоАП |

Сканер смотрит главную страницу и до трёх внутренних (контакты, запись, курсы, оплата), формы во встроенных окнах (виджеты GetCourse и т. п.), сетевые запросы и cookie. Он скачивает политику, в том числе через раздел «Правовая информация», и проверяет, что она открывается, есть ли в ней реквизиты и упоминаются ли аналитика и трансграничная передача.

Если сканер не уверен, он предпочитает промолчать, а не обвинить зря. Например:
- если политика в PDF, он не утверждает, что в ней чего-то нет;
- скрытые служебные копии галочек не считаются отмеченными.

## Установка

Нужен [Node.js](https://nodejs.org) версии 18 или новее.

```bash
cd fz152
npm install
npx playwright install chromium
```

## Настройка

Скопируйте `config.example.json` в `config.json` и впишите свои данные: название, имя, контакты, цены, срок работы. Они попадут в отчёты и письма. `config.json` не попадает в git.

## Запуск

```bash
node scan.js sites.txt                     # список сайтов из файла, по одному в строке
node scan.js school.ru art-studio.ru       # или прямо в командной строке
node scan.js sites.txt --concurrency 4 --pages 3
```

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `--out <папка>` | `output` | куда сохранять результаты |
| `--concurrency <N>` | 3 | сколько сайтов проверять одновременно |
| `--pages <N>` | 3 | сколько внутренних страниц смотреть на сайте |
| `--config <файл>` | `config.json` | файл с вашими данными |

Скорость — примерно 15 сайтов за 2–3 минуты при `--concurrency 4`.

Результаты сохраняются в `output/<дата_время>/`:
- `index.html` — сводная таблица со ссылками на отчёты и письма;
- `leads.csv` — то же для Excel: разделитель «;», кодировка корректно открывается в русском Excel;
- `reports/` — отчёты для клиентов;
- `letters/` — черновики писем;
- `results.json` — все данные проверки: какие формы, документы и сервисы нашлись.

## Как использовать в работе

1. Соберите список сайтов ниши в `sites.txt`: онлайн-школы, эксперты, клиники и т. п.
2. Запустите сканер и откройте `index.html`. Начинайте с верхних строк — там больше всего замечаний.
3. Перед отправкой откройте отчёт и проверьте замечания глазами.
4. Проверьте компанию в [реестре операторов Роскомнадзора](https://pd.rkn.gov.ru/operators-registry/operators-list/) по ИНН из таблицы. Отсутствие в реестре — сильный аргумент для письма. Из-за рубежа сайт реестра обычно не открывается, поэтому проверка ручная.
5. Сохраните отчёт в PDF и отправьте письмо из `letters/`. Шаблоны повторного письма, письма партнёрам и ответов на возражения — в [`templates/letters.md`](templates/letters.md).
6. После оплаты отправьте клиенту анкету [`templates/anketa.md`](templates/anketa.md). По ней готовятся документы, их проверяет юрист.

## Тесты

```bash
npm test
```

Сканер прогоняется на 12 тестовых страницах из `test/fixtures/`: правильный сайт, разные нарушения, «ловушки» вроде формы поиска в карте, политики в PDF, кодировки windows-1251 и скрытых копий галочек GetCourse.

## Ограничения

- Отчёт — автоматическая проверка по открытым признакам, а **не юридическое заключение**. Внутренние документы, меры защиты и уведомление в Роскомнадзор по сайту не видны.
- Тексты замечаний и суммы штрафов основаны на отраслевых публикациях на ноябрь 2026 года, а не на заключении юриста. Перед запуском продаж их должен проверить юрист: законы меняются.
- Сайты с защитой от ботов могут не открыться — они попадут в таблицу с пометкой «ошибка».
